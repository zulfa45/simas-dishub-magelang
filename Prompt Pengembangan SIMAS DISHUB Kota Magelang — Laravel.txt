# SIMAS DISHUB KOTA MAGELANG

## Sistem Informasi Manajemen Surat Berbasis Laravel

Bangun sebuah **web application internal bernama "SIMAS DISHUB KOTA MAGELANG" (Sistem Informasi Manajemen Surat)** untuk lingkungan **Dinas Perhubungan Kota Magelang**.

Aplikasi digunakan untuk mengelola seluruh alur surat masuk secara digital mulai dari:

**SURAT MASUK → PEMBERITAHUAN → PENUGASAN/DISPOSISI → NOTIFIKASI → KARYAWAN → TANGGAPAN → TINDAK LANJUT → SELESAI → ARSIP**

Aplikasi **WAJIB dibangun menggunakan Laravel** dan jangan menggunakan PHP Native sebagai framework utama.

# 41. WORKFLOW DETAIL

## Workflow Surat

1. Staf login.
2. Membuka Surat Masuk.
3. Klik Tambah Surat.
4. Mengisi data.
5. Upload file.
6. Sistem membuat nomor agenda.
7. Surat disimpan.
8. History dibuat.
9. Audit log dibuat.
10. Surat muncul di dashboard.

## Workflow Pemberitahuan

1. Staf membuka detail surat.
2. Klik "Buat Pemberitahuan".
3. Mengisi judul dan isi.
4. Memilih target.
5. Publish.
6. Sistem membuat recipient.
7. Sistem membuat notification.
8. Penerima melihat bell notification.
9. Ketika dibuka, status menjadi read.
10. History dibuat.

## Workflow Penugasan

1. Staf membuka surat.
2. Klik "Buat Penugasan".
3. Masukkan instruksi.
4. Pilih bagian/karyawan.
5. Tentukan deadline.
6. Simpan.
7. Recipient dibuat.
8. Notification dibuat.
9. Status tugas = Belum Dibaca.
10. History dibuat.

## Workflow Karyawan

1. Karyawan login.
2. Melihat notification.
3. Membuka tugas.
4. Status → Dibaca.
5. Klik Terima Tugas.
6. Status → Diterima.
7. Mulai bekerja.
8. Status → Dalam Proses.
9. Memberikan tanggapan.
10. Upload bukti.
11. Status → Selesai.
12. Staf mendapatkan notification.
13. History dibuat.

## Workflow Arsip

1. Semua tugas selesai.
2. Surat berstatus selesai.
3. Admin/Staf melakukan arsip.
4. Status surat → Diarsipkan.
5. History dibuat.
6. Audit log dibuat.

# 43. ATURAN CODING

Saat implementasi:

1. Gunakan Laravel sesuai best practice.
2. Jangan menggunakan PHP Native sebagai pengganti Laravel.
3. Gunakan Eloquent ORM.
4. Gunakan Migration.
5. Gunakan Seeder.
6. Gunakan Factory.
7. Gunakan Form Request.
8. Gunakan Policy/Gate.
9. Gunakan Middleware.
10. Gunakan Service Layer untuk business logic kompleks.
11. Gunakan Blade Component untuk UI berulang.
12. Gunakan reusable component untuk button, modal, table, badge, alert, form.
13. Jangan mengulang kode yang sama.
14. Gunakan database transaction untuk proses multi-table yang harus atomik.
15. Gunakan eager loading untuk mencegah N+1 query.
16. Gunakan pagination.
17. Gunakan validation sebelum menyimpan data.
18. Jangan percaya input dari frontend.
19. Seluruh permission harus diverifikasi di server.
20. File privat tidak boleh diakses langsung tanpa authorization.
21. Gunakan `.env` untuk konfigurasi sensitif.
22. Jangan menyimpan password dalam plaintext.
23. Jangan hardcode password database.
24. Jangan hardcode secret key.
25. Jangan menghapus data penting secara permanen tanpa permission.
26. Gunakan soft delete jika sesuai.
27. Setiap aktivitas penting harus masuk history/audit log.
28. Gunakan database transaction pada workflow surat, pemberitahuan, dan penugasan.
29. Buat kode modular dan scalable.
30. Jangan membuat fitur yang tidak diminta tanpa alasan teknis yang jelas.
